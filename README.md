# ZYNQEL бот v2.6

Бот 24/7 следит за funding на Binance и пишет в Telegram-канал входы, ведёт каждую сделку до закрытия и по понедельникам присылает итоги недели.

Новое в v2.6: **движок смотрит на несколько факторов движения монеты**, а не только на funding.

Я проверил 9 признаков (глубина падения funding, уровень funding, движение цены за 3 дня, положение к EMA20, RSI, поток агрессивных покупок/продаж, объём, волатильность, движение BTC). Засчитаны только те, что улучшают результат и на истории, и на свежих данных июнь–октябрь 2026:

- Лонг: ✅ funding упал очень сильно (−3σ и больше) · ✅ цена откатилась за 3 дня · ✅ вчера продавцы давили.
- Шорт мема: ✅ вчера покупатели гнались · ✅ BTC рос 3 дня.

За каждый фактор балл. **0 баллов — сигнал не присылается** (такие сделки исторически около нуля), все баллы — 🔥 сильный (риск 1%), остальное — обычный (риск 0.5%). В сообщении видно, какие факторы выполнены.

| | История до июня 2026 | Новые июнь–окт 2026 |
|---|---|---|
| Лонги, все (v2.5) | +1.57% на сделку | +0.85% |
| Лонги, 1+ балл (v2.6) | +2.00%, 65% в плюс | +1.15%, 59% в плюс |
| Лонги, 0 баллов (отсеяны) | −0.31% | −0.01% |
| Шорты мемов, все (v2.5) | +1.32% | +0.81% |
| Шорты мемов, 1+ балл (v2.6) | +1.78%, 67% в плюс | +1.54%, 78% в плюс |

Не помогли (или работали наоборот): уровень funding, RSI, положение к EMA20, объём, волатильность. Наблюдение на будущее: лонги заметно лучше, когда цена выше 20-дневной средней (откат в восходящем тренде); это не было задано заранее, поэтому пока не используется, бот копит данные для проверки.

Новое в v2.5:
- **Оценка силы сигнала по новым данным: поток агрессивных покупок и продаж** (есть в дневных свечах Binance). Лонг 🔥 сильный, если вчера продавцы давили сильнее обычного; шорт 🔥 сильный, если покупатели гнались сильнее обычного.
- На истории и на свежих данных сильные сигналы заметно лучше. Прогон бота по 2025 – октябрь 2026: 🔥 сильные 63 сделки, 63% в плюс, +1.8% на сделку; обычные 71 сделка, 45% в плюс, −0.5%.
- Поэтому риск разный: 🔥 сильный — 1% депозита, обычный — 0.5%. Бот сам пишет размер позиции.
- `ONLY_STRONG=1` — присылать только сильные сигналы (их примерно половина).
- В /stats и в итогах недели результаты видны отдельно по сильным и обычным.

Новое в v2.4:
- **Шорты мемов снова включены, но по новому правилу:** funding за сутки вырос необычно сильно для этой монеты (больше 2σ) и BTC ниже EMA50. Это правило в плюсе во всех периодах: 2023–24 (PF 1.72), 2025 – май 2026 (PF 1.35) и на свежих данных июнь–октябрь 2026 (17 сделок, 65% в плюс, +0.8% на сделку). Старое правило с фиксированным порогом на свежих данных было в минусе. Выключить: `MEME_SHORTS=0`.
- Мемы: PEPE, SHIB, FLOKI. BONK убран (выплаты раз в 4 часа и минус на собственной истории).
- Шорты основных монет по-прежнему не даём: проверены и с фиксированным порогом, и с 2σ, на истории везде минус.

Новое в v2.3:
- **Порог входа свой для каждой монеты.** Раньше лонг давался при падении funding на 0.012% за сутки для всех монет. У BTC funding почти никогда так не падает, а у NEAR это обычный шум. Теперь вход, когда падение за сутки сильнее 2σ от обычного для этой монеты за последние ~30 дней.
- Правило задано до проверки и проверено на свежих данных июнь–октябрь 2026: 43 сделки, 58% в плюс, +0.85% на сделку (было 30 сделок, 50%, +0.31%). На истории 2024 тоже лучше: 61% в плюс, +1.6% на сделку.

Новое в v2.2 (после проверки на свежих данных июнь–октябрь 2026):
- **Шорты мемов выключены по умолчанию.** На новых данных они были в минусе (−0.4% на сделку). Включить можно переменной `MEME_SHORTS=1`.
- **Учёт выплат funding раз в 4 часа.** Binance переводит некоторые монеты на выплаты раз в 4 часа; теперь бот пересчитывает ставки к 8-часовым и всегда сравнивает за 24 часа.
- **TON убран:** у него выплаты раз в 4 часа, и после правильного пересчёта преимущества на истории нет.

Новое в v2.1: бот копит рыночные данные (открытый интерес, соотношение лонгов и шортов, поток покупок/продаж) по всем монетам каждые 6 часов. Binance хранит их только 30 дней, а нам они нужны, чтобы через 2–3 месяца проверить идею «funding + OI». На сигналы это пока не влияет.

## Что изменилось по сравнению с v1

| | v1 | v2 |
|---|---|---|
| Основные монеты | лонг и шорт | **только лонг**, когда funding за сутки падает необычно сильно для монеты (BTC, ETH, SOL, XRP, DOGE, LINK, LTC, NEAR) |
| Мемы | шорт | шорт PEPE, SHIB, FLOKI при необычном росте funding (2σ) и BTC ниже EMA50 |

| Срок | 3 дня | до 6 дней |
| Фильтр страха/жадности | был | убран (вырезал лучшие сделки) |
| Убраны | | шорты основных, TON, BONK, AVAX и SUI (нет истории для проверки), WIF, ARB, OP, INJ, SEI, TIA |
| Память | терялась при перезапуске | сохраняется в файл, после перезапуска старые сигналы не дублируются |

Лонги v2.3 на истории до июня 2026: 62% сделок в плюс, в среднем +1.5% на сделку. На свежих данных июнь–октябрь 2026: 58% в плюс, +0.85% на сделку без комиссий (43 сделки). Это небольшая выборка, одна сделка колеблется примерно на ±5%, поэтому смотри итоги недели и держи риск маленьким.

## Как обновить (5 минут)

1. Открой на GitHub репозиторий бота `zynqel_bot-`.
2. **Add file → Upload files**, перетащи три файла: `zynqel-bot.js`, `package.json`, `README.md`. Они заменят старые.
3. Внизу нажми **Commit changes**.
4. Railway сам заметит изменения и перезапустит бота (вкладка Deployments, статус станет Active).
5. В канал придёт «✅ ZYNQEL бот v2 запущен».

Переменные в Railway остаются те же: `BOT_TOKEN` и `CHAT_ID` (с минусом: `-100…`). Регион сервера должен остаться **Европа**, иначе Binance не отвечает.

## Диск для памяти (нужен для сбора данных)

Без диска бот после каждого обновления на GitHub забывает открытые сделки и всё, что накопил по OI.

В Railway: правый клик по карточке бота → **Attach Volume** (или кнопка **+ Create** → Volume, затем подключить к боту) → Mount path: `/data` → сохранить. В логах бота после этого будет «на диске Railway».

## Личные команды (статистика и файлы)

1. В Telegram открой своего бота **@ZynqelBot** (не канал, а сам бот) и нажми **Start**.
2. Он ответит «Твой chat id: 123456789».
3. В Railway → Variables добавь `ADMIN_CHAT_ID` = это число. Бот перезапустится сам.
4. Теперь в личке бота работают команды:
   - `/stats` — сколько сделок закрыто, сколько в плюс, средний результат, что открыто сейчас;
   - `/data` — бот пришлёт два файла: накопленные рыночные данные и все сделки. Их можно переслать мне для проверки.

## Настройки (Railway → Variables)

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather | обязательно |
| `CHAT_ID` | id канала, например `-1004233757429` | обязательно |
| `POLL_MINUTES` | как часто проверять рынок | 5 |
| `SEND_WATCH` | `0` = не слать «наблюдение» | 1 |
| `WEEKLY_REPORT` | `0` = без итогов недели | 1 |
| `ADMIN_CHAT_ID` | твой chat id для команд /stats и /data | нет |
| `MEME_SHORTS` | `0` = выключить шорты мемов | 1 |
| `ONLY_STRONG` | `1` = присылать только 🔥 сильные сигналы | 0 |

## Как читать сигнал

- **Вход** — цена на момент сигнала.
- **Стоп** — сразу ставь его на бирже (Stop Loss по цене). Бот проверяет цену раз в 5 минут, биржевой стоп срабатывает мгновенно.
- **Цель 1** — закрыть половину позиции, стоп остатка перенести на цену входа.
- **Цель 2** — закрыть остаток.
- **🔥 Сильный / обычный и ✅/▫️ факторы** — какие подтверждения движения выполнены. Сильные исторически заметно лучше.
- **«Риск 1% (или 0.5%) депозита → позиция ≈ X%»** — при таком размере позиции срабатывание стопа стоит 1% (0.5%) депозита. На мемах стоп шире, поэтому позиция меньше.
- Убыточные сделки часто идут подряд по нескольким монетам сразу. Это нормально для стратегии, поэтому риск на сделку маленький.

Не финансовая рекомендация.
